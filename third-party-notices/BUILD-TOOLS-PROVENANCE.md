# Build tool and runtime provenance

The Gradle wrapper was generated by the unmodified Gradle 8.13 distribution.
The generated shell/batch launchers and wrapper JAR retain their upstream
Apache 2.0 terms; they are build infrastructure and are not the MP3 engine.

- Distribution: <https://services.gradle.org/distributions/gradle-8.13-bin.zip>
- Distribution SHA-256: `20f1b1176237254a6fc204d8434196fa11a4cfb387567519c61556e8710aed78`
- SHA-256 independently obtained from <https://services.gradle.org/distributions/gradle-8.13-bin.zip.sha256>
- Generated wrapper JAR SHA-256: `81a82aaea5abcc8ff68b3dfcb58b3c3c429378efd98e7433460610fecd7ae45f`
- Retained notices: `Gradle-LICENSE.txt`, `Gradle-NOTICE.txt`.

The native Android binary statically links libc++ and associated C++ runtime
components supplied by Android NDK `27.2.12479018` (r27c). Its LLVM toolchain
reports `18.0.3`, based on `r522817c`. The unmodified notice from
`toolchains/llvm/prebuilt/linux-x86_64/NOTICE` is retained in
`Android-NDK-r27c-LLVM-NOTICE.txt`. It includes the Apache 2.0 with LLVM
exceptions terms and the relevant libc++/libc++abi notices. Some notices in
this aggregate concern toolchain components that are not linked into this AAR.
No runtime implementation is claimed to have been relicensed to MIT.

The Android module automatically embeds project and third-party notices in
`classes.jar` under `META-INF/android-mp3-encoder/` when packaging the AAR.

The Kotlin standard library is a transitive Maven dependency under Apache 2.0;
it is resolved by the consuming Android build. Android SDK/Gradle/Kotlin
compiler components are build dependencies, not bundled MP3 encoders.
